圆角系统对比展示

三种不同的圆角实现方式，适用于不同的开发场景和需求

G2

2rem / 32px

Tailwind配置扩展

<!-- CSS 定义 -->
.radius-g2 {
  border-radius: 2rem;
}

<!-- HTML 使用 -->
<div class="radius-g2">
  Content
</div>
✓

优点

  • • 全局统一管理
  • • 易于维护和修改
  • • 可复用性强
  • • 符合设计系统规范
✗

缺点

  • • 需要额外CSS文件
  • • 增加CSS体积
  • • 需要配置Tailwind

推荐使用场景

大型项目 设计系统 团队协作
G2.5

2.5rem / 40px

CSS变量方式

<!-- CSS变量定义 -->
:root {
  --radius-g2-5: 2.5rem;
}

.radius-g2-5 {
  border-radius: var(--radius-g2-5);
}

<!-- HTML 使用 -->
<div class="radius-g2-5">
  Content
</div>
✓

优点

  • • 动态可配置
  • • 可通过JS修改
  • • 主题切换友好
  • • 支持媒体查询
✗

缺点

  • • 浏览器兼容性(IE11-)
  • • 调试时不易查看计算值
  • • 需要理解CSS变量作用域

推荐使用场景

主题切换 动态样式 多品牌系统

💡 最佳实践建议

1. 混合使用策略

在大型项目中，建议使用Tailwind配置扩展作为主要方式，建立统一的设计系统。对于需要动态调整的场景，使用CSS变量。仅在快速原型或一次性组件中使用JIT任意值。

2. 设计Token管理

将圆角值定义为设计Token，使用CSS变量存储，并在Tailwind配置中引用。这样可以同时享受全局管理和动态调整的优势。

:root { --radius-g2: 2rem; }

3. 语义化命名

使用语义化的类名，如 .radius-card、.radius-button 而非 .radius-32，使代码更易理解和维护。

4. 文档与规范

建立清晰的设计系统文档，明确每种圆角的使用场景和规范。定期进行代码审查，确保团队成员遵循统一标准。
